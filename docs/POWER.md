# Power v0.2

Как часы берегут батарею: шторка гасит экран, когда к часам не прикасаются, погашенный экран не
рисуется, а T-Watch 2020 с погашенным экраном спит лёгким сном.

## Changelog

- **v0.2**: Лёгкий сон T-Watch 2020 при погашенном экране, по настройке `power.light_sleep` (пока
  выключена). Настройки — консолью: `sys config <ключ> [значение]`.
- **v0.1**: Погашенный экран не рисуется: пока подсветка выключена, LVGL не обновляет экран; при
  пробуждении экран рисуется целиком, раньше, чем включится подсветка.

---

## Без касаний

Когда в шторке включено «Авто» (`power.auto_sleep`), шторка (`ui_shade.cpp`) раз в секунду смотрит,
сколько к экрану не прикасались:

| Без касаний | Что | Настройка в `/system/config.yml` |
|---|---|---|
| 30 с | подсветка чуть тусклее: 230 из 255 | `power.nudge_timeout` |
| 45 с | тусклая: 90 | `power.dim_timeout` |
| 60 с | сон | `power.sleep_timeout` |

Первое касание после любого шага только будит экран: его берёт прозрачный блокировщик шторки, а
приложение не получает.

## Сон

- Подсветка выключена.
- LVGL не рисует (`display_sleep()`): таймер обновления экрана стоит, изменения не отмечаются —
  иначе первое же изменение снова запустило бы таймер. Приложение работает дальше: таймеры, Lua,
  состояние.
- При пробуждении (`display_wake()`) экран рисуется целиком, раньше, чем включится подсветка:
  старая картинка не мелькает.
- Касание читается как всегда и будит экран.

Проверка — в симуляторе: робот `sim/tests/tela_sleep.sim` (секундомер идёт, а во сне экран не
рисуется ни разу) и раздел отчёта PR «Перерисовка в покое» (`docs/SIMULATOR.md`).

## Лёгкий сон

Пока экран спит, рисовать нечего, и процессору незачем работать между проходами цикла: вместо
`delay(5)` он может спать лёгким сном (`Power::rest()`), пока не подойдёт следующий таймер LVGL — в
том числе чтение касания, раз в 33 мс, — или пока касание само не разбудит чип. Лёгкий сон — когда
всё сразу:

| Условие | Почему |
|---|---|
| `power.light_sleep: true` | пока не проверено на часах — выключено |
| экран спит | иначе есть что рисовать |
| BLE выключен | контроллеру BLE нужны основные часы: во сне связь рвётся |
| у приложения не идут таймеры `<timer>` | это таймеры FreeRTOS, а во сне время FreeRTOS стоит: секундомер встал бы. Таймеры Lua (`timer.once`, `timer.interval`) — таймеры LVGL, они идут по `millis()` и спать не мешают |
| плата умеет | `Device::lightSleep()`; умеет T-Watch 2020 |

Касание будит экран как всегда: шторка ловит его при следующем чтении (не позже 33 мс сна). Без
касания часы просыпаются только к таймерам: в лаунчере — раз в 33 мс на чтение касания, раз в
секунду — часы и шторка. Каждое пробуждение — один короткий проход цикла, остальное время чип спит.

**T-Watch 2020** (`TWatch2020::lightSleep()`): будит таймер (`esp_sleep_enable_timer_wakeup`) и
линия INT контроллера касания FT6336 — GPIO 38, низкий уровень, пока палец на стекле. Если INT
уже низкий (палец ещё на стекле или линия не отпускается) — только таймер: иначе чип просыпался бы
сразу же, раз за разом. После сна цикл уступает остальным задачам 1 мс (`delay(1)`): сторожевой
таймер кормит задача простоя.

**Панели** ESP32-S3 4848S040 и 8048W550 не спят: у них нет батареи, а линия INT касания на них не
выведена (`PIN_TOUCH_INT -1`).

**Пока часы спят**, USB-консоль не слышит: строки, пришедшие во сне, теряются. Коснуться экрана — и
консоль снова слушает.

### Включить и проверить

```
sys config power.light_sleep true
```

Настройка сохраняется в `/system/config.yml` и действует сразу. Через минуту без касаний экран
гаснет, часы спят. При пробуждении — строка в логе, сколько спал экран и сколько из этого чип; в
симуляторе после 6 с сна:

```
[I][Power] display asleep 6178 ms, light sleep 5987 ms in 186 naps
```

Выключить — `sys config power.light_sleep false`.

Проверка в симуляторе: робот `sim/tests/tela_light_sleep.sim`. Плата симулятора спит, как T-Watch:
время идёт, цикл стоит; робот проверяет, сколько она проспала (`expect slept.ms`): в лаунчере —
спит, у секундомера с `<timer>` — нет, с выключенной настройкой — нет.
