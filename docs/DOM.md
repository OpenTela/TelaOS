# DOM v0.5

DOM в TelaOS: элементы приложения для его скрипта на Lua — так, как браузер даёт их JavaScript.
Браузер без JS — всё остальное должно быть: HTML (`docs/HTML_TAGS.md`), CSS (`docs/CSS.md`)
и DOM.

## Changelog

- **v0.5**: События: `addEventListener`, `removeEventListener`, `preventDefault`, `stopPropagation`.
  `click`, `input`, `change` идут вверх по предкам, `focus` и `blur` — нет. `preventDefault()`
  отменяет то, что TelaOS делает сама: переход по ссылке, `<details>`, закрытие `<dialog>`.
- **v0.4**: `el.style` — свойства `style=""` по одному: `el.style.color`, `el.style.backgroundColor`,
  `cssText`, `setProperty`, `removeProperty`. Смена применяет CSS заново. `style=""` разметки
  теперь берут и виджеты TelaOS (`<label>`, `<button>`, `<div>`…), не только элементы HTML.
- **v0.3**: `querySelector` и `querySelectorAll` — у `document` и у элемента. Селекторы — те же,
  что читает CSS TelaOS; состояние (`:checked`, `:disabled`) — то, в каком элемент сейчас.
- **v0.2**: `classList`: `add`, `remove`, `toggle`, `contains`; к ним `el.className`. Смена класса,
  `id` или атрибута, на который смотрит селектор, применяет CSS заново — к элементу, к тому, что
  в нём, и к соседям после него. Свойства правил, которые перестали подходить, возвращаются
  к тому, что было до них.
- **v0.1**: Дерево элементов и первые методы: `document.getElementById`, `textContent`,
  `getAttribute`, `setAttribute`, `removeAttribute`; к ним `hasAttribute`, `id`, `tagName`.
  `setAttribute` делает то, что атрибут делает в разметке: `hidden`, `disabled`, `checked`, `value`…

## Как это выглядит

```lua
local title = document.getElementById("title")
title.textContent = "Привет"
document.getElementById("send"):setAttribute("disabled", "")
if title:hasAttribute("hidden") then title:removeAttribute("hidden") end
```

- Методы — через двоеточие: `el:setAttribute("a", "b")`; свойства — через точку: `el.textContent`.
  `document.getElementById(id)` и `document:getElementById(id)` — одно и то же.
- Элемент — одно и то же значение Lua, сколько его ни ищи: `a == b`, и он годится в ключи таблицы.
- Свойство, которого нет, читается как `nil`, а записать его — ошибка: опечатка
  `el.textcontent = "…"` не пройдёт молча.
- Значение `setAttribute` и `textContent` превращается в строку, как в браузере: `5` — `"5"`;
  `nil` — пустая строка.

## Где живёт дерево

- Дерево записывается, пока строятся страницы: у элемента начинается и кончается содержимое
  (`UI::CssScope`), и он получает объект LVGL, когда его стилизуют (`Widget::applyCss`).
  Движок: `src/ui/dom.cpp`, для Lua — `src/engines/lua/lua_dom.cpp`.
- В дереве все страницы приложения, скрытые тоже. Порядок — как в разметке.
- Атрибуты хранятся, как написаны. `getAttribute` раскодирует `&amp;`, `&quot;`, `&lt;`…
- Новое приложение — новое дерево: элемент прежнего ничего не находит (`textContent` пуст,
  `getAttribute` — `nil`).

## Атрибуты на экране

| Атрибут | Что делает |
|---------|------------|
| `hidden` | прячет элемент, снятый — показывает |
| `disabled` | выключает кнопку, поле, флажок, переключатель |
| `checked` | флажок, переключатель; радио выключает остальные с тем же `name` |
| `value` | текст поля, положение ползунка |
| `placeholder` | подсказка поля |
| `open` у `<dialog>` | показывает диалог, снятый — прячет |
| `id` | `getElementById` и `ui.*` находят элемент по новому |
| `bgcolor`, `color`, `visible`, `x`, `y`, `w`, `h`, `z-index` | как `ui.setAttr()` |
| `class`, `style` | CSS применяется заново (ниже) |
| остальные: `title`, `data-*`… | хранятся: `getAttribute` вернёт их. Если на атрибут смотрит селектор (`[data-tone]`), CSS применяется заново |

- Логический атрибут (`hidden`, `disabled`, `checked`, `open`) включён при любом значении, кроме
  `false` и `0` — как в разметке TelaOS: `setAttribute("hidden", "")` прячет,
  `setAttribute("hidden", "false")` показывает.
- `checked` и `value` из скрипта не вызывают `onchange` и не пишут в `bind=`: браузер тоже не
  шлёт событий, когда поле меняет скрипт.
- Снятый атрибут TelaOS (`bgcolor`, `x`…) не возвращает прежний вид: остаётся последний.

## Классы и CSS

- Смена класса, `id` или атрибута, на который смотрит селектор (`[data-tone="hot"]`), применяет
  CSS заново: к самому элементу, к тому, что в нём (`.dark p`), и к соседям после него
  (`.lead + p`, `.a ~ li`). Места среди соседей (`li:first-child`) считаются по дереву.
- Свойства правил, которые перестали подходить, возвращаются к тому, что было до них: цвет из
  `color=`, вид элемента HTML, тема LVGL. Снятый `.hide { display: none }` снова показывает элемент —
  если у него нет `hidden`.
- Что после CSS поставили атрибут TelaOS, привязка или скрипт (`ui.setAttr`, `bgcolor="{c}"`),
  остаётся: CSS его больше не трогает.
- `class="{var}"`: `classList` видит слова, как они подставлены сейчас. После первой правки
  класс — скрипта: `{var}` его больше не меняет.

## Стиль

```lua
local title = document.getElementById("title")
title.style.color = "#4FC3F7"
title.style.fontSize = "24px"
title.style.display = "none"  -- спрятать
title.style.display = ""      -- снять: снова как по CSS
```

- `el.style.<свойство>` — объявление в `style=""` элемента. `backgroundColor` — это
  `background-color`, можно и `el.style["background-color"]`. Чтение — значение, как записано,
  или `""`.
- Запись переписывает `style=""`, как его пишет браузер (`color: red; width: 10px;`), и применяет
  CSS заново. `style=""` — после листов, а `!important` листа бьёт его, как в CSS (`docs/CSS.md`).
- `""` или `nil` снимает свойство: возвращается то, что было без него, — правило листа, вид элемента.
- `el.style.cssText` — весь `style=""`; `el.style = "…"` — то же.
- `setProperty(name, value, "important")`, `getPropertyValue(name)`, `getPropertyPriority(name)`,
  `removeProperty(name)` — с именами, как в CSS: `background-color`, `--accent`. `--accent`
  получает и то, что внутри элемента.
- Значение из нескольких объявлений (`"red; width: 0"`) и имя с пробелом браузер оставляет без
  внимания — TelaOS тоже.

## События

```lua
local card = document.getElementById("card")
card:addEventListener("click", function(e)
  print(e.type, e.target.id, e.currentTarget.id)  -- click ok card
end)
document.getElementById("more"):addEventListener("click", function(e)
  e:preventDefault()  -- ссылка не переходит
end)
```

- `el:addEventListener(type, fn)` — `fn(e)` на событие элемента. Типы:
  - `click` — касание;
  - `input` — значение меняется: у поля — при каждой букве, у ползунка — пока его тянут, у флажка
    и списка — сразу;
  - `change` — значение готово: ползунок отпустили, у поля нажали OK, флажок и список — сразу;
  - `focus`, `blur` — поле получило фокус и потеряло его.

  Другой тип — ошибка.
- Одна функция на один тип добавляется один раз, как в браузере. `removeEventListener(type, fn)`
  снимает её — нужна та же функция, а не такая же.
- `click`, `input`, `change` идут вверх, как в браузере: от элемента, где случились, по его предкам.
  Так у карточки срабатывает касание её кнопки. `e.target` — где случилось, `e.currentTarget` —
  чей слушатель работает сейчас. `focus` и `blur` вверх не идут.
- `e:stopPropagation()` — к предкам событие не идёт; остальные слушатели этого же элемента его
  получат.
- `e:preventDefault()` — TelaOS не делает того, что сделала бы сама: ссылка не переходит
  (`<a href>` и `href=` у кнопки), `<details>` не открывается и не закрывается, кнопка `<dialog>`
  его не закрывает, `<label>` не передаёт касание своему полю. `e.defaultPrevented` — отменено ли.
- Слушатели работают раньше `onclick=` разметки. Ошибка в одном не мешает следующему: она в логе.
- Элемент со слушателем `click` принимает касания, даже `<div>` и `<label>`.
- `e` живёт, пока работают слушатели: сохранённый на потом, он пустой.

## Поиск по селекторам

```lua
for _, box in ipairs(document:querySelectorAll("#settings input:checked")) do
  print(box.id)
end
local open = document.getElementById("todo"):querySelector("li:not(.done)")
```

- `document:querySelector(s)` ищет на всех страницах приложения, скрытых тоже.
  `el:querySelector(s)` — только в элементе, без него самого. Предки элемента при этом считаются,
  как в браузере: у `#sub` внутри `.menu` найдётся `.menu .item`.
- Селекторы — те же, что читает CSS (`docs/CSS.md`): тип, `.class`, `#id`, `[attr]`, комбинаторы,
  место среди соседей, `:not()`, `:is()`, `:where()`. Тип — без учёта регистра.
- В списке через запятую (`h2, .note`) каждый элемент находится один раз и в порядке страницы,
  а не списка.
- Состояние — то, в каком элемент сейчас. `:checked` — отмеченный флажок или выбранное радио,
  даже если его отметил палец, а не атрибут; `[checked]` — сам атрибут. `:disabled` — выключенный,
  `:focus` — поле в фокусе, `:active` и `:hover` — нажатый.
- Селектор, который CSS не читает, — ошибка, как `SyntaxError` в браузере: `""`, `a[`,
  `p::before`. Если такой есть в списке, ошибка — весь список.
- Метод элемента — через двоеточие: `el.querySelector(s)` с точкой — ошибка.

## textContent

- Чтение — текст, как его видно: у надписи и абзаца — весь их текст, с `<b>`, `<a>` внутри;
  у кнопки — её надпись; у блока — тексты того, что в нём, подряд. У `<li>` — без маркера,
  у `<details>` — без `+`.
- У `<input>`, `<img>`, флажка, ползунка, переключателя текста нет: пустая строка, как в браузере.
- Пробелы между блоками разметки не сохраняются: `<p>a</p> <p>b</p>` читается `ab`.
- Запись ставит текст вместо содержимого. Элементы, что были внутри, уходят из дерева:
  `getElementById` их не находит, а у найденных раньше `textContent` пуст.
- `{var}` разметки после записи текст не трогает: у `<p id="c">{count}</p>` после
  `c.textContent = "—"` строка остаётся «—», как бы `count` ни менялся.
- У `<input>`, `<img>`, ползунка запись ничего не меняет.

## Ограничения

- Строчный элемент в тексте (`<b>`, `<span>`, `<a>` в абзаце) — в дереве, с атрибутами, но без
  своего объекта: абзац рисуется одним объектом LVGL. `textContent` у него пуст, а запись и
  `hidden` экран не меняют. Текст, который меняет скрипт, дайте блоку: `<p id="x">`, `<label id="x">`.
- `getAttribute` — как в разметке: у `class="{theme}"` вернёт `{theme}`, без подстановки.
- Текущие значения полей (`el.value`, `el.checked`) — пока нет: только атрибуты.
- Строки `<list>` — не элементы: их строят данные, а не разметка.
- CSS применяется заново только к тому, к чему его применило построение страницы: строчный
  элемент в тексте свой вид не меняет (он — часть текста абзаца), а картинки, страницы и вкладки
  CSS не берут и так.
- Свойство, которое прежние правила не трогали, новое правило ставит и поверх атрибута TelaOS:
  `bgcolor=` у кнопки без фона в CSS уступит классу с `background`.
- `z-index` из класса заново не применяется.
- Состояние в селекторе — только у самого элемента, как и в CSS: `:checked + label`,
  `li:active a` и `input:not(:checked)` — ошибка. Нет и `:scope`, `:has()`, `:empty`.
- `::placeholder` ничего не находит: это не элемент. `:root` — тоже: у приложения нет `<html>`.
- `el.style` хранит значение, как записано: браузер запишет `#F00` как `rgb(255, 0, 0)`, а TelaOS
  — как есть. Значение, которое CSS не читает, экран не меняет, но в `style=""` остаётся.
- `el.style` — только `style=""`; итога CSS (`getComputedStyle`) нет.
- Строчный элемент в тексте (`<a>` в абзаце) событий не получает: своего объекта у него нет.
  Слушателя дайте абзацу.
- У флажка и переключателя `preventDefault()` в `click` отметку не отменяет: LVGL ставит её раньше.
- У `document` слушателей нет: дайте их странице (`<page id="main">`), до неё события доходят.
  Третьего аргумента (`capture`, `once`) тоже нет.
