# Simulator v0.3

Настоящая прошивка TelaOS на ПК: тот же `src/`, LVGL 9.2 из `lib/lvgl`, `include/lv_conf.h`,
шрифты, Lua, `data/`. Окно, где мышь — палец; робот, который тапает и проверяет; скриншоты
каждого экрана каждого приложения — и их сравнение в каждом PR, картинками и словами.

## Changelog

- **v0.3**: Счётчик «сишных» мест: `sim/tools/code_meter.py`, в отчёте PR — сколько их было
  и стало в `src/`.
- **v0.2**: Изменения словами: `sim/tools/tree_diff.py` сравнивает деревья виджетов «до» и
  «после», в отчёте PR — раздел «Что изменилось». В дереве `tree` — id, которые элементам дал
  автор приложения.
- **v0.1**: Симулятор в репозитории (`sim/`), робот, скриншоты всех страниц всех приложений,
  проверка PR в GitHub Actions: TelaCI + экраны «до / после / разница» комментарием в PR.

## Сборка и запуск

Ubuntu 24.04: `sudo apt install cmake ninja-build libsdl2-dev libpng-dev libmbedtls-dev`

```bash
cmake -S sim -B build/sim -G Ninja && cmake --build build/sim
build/sim/telaos_sim                                                  # окно, мышь = палец
build/sim/telaos_sim --zoom 2                                         # окно крупнее
build/sim/telaos_sim --headless --script sim/tests/tela_hello.sim --out shots
```

| Ключ | Что делает |
|------|-----------|
| `--headless` | без окна: время идёт так быстро, как считает процессор |
| `--script <file>` | сценарий робота (можно несколько) |
| `--run "<команды>"` | команды робота прямо в строке, через `;` |
| `--out <dir>` | куда класть скриншоты и деревья (`shots`) |
| `--data <dir>` | что «прошить» в LittleFS (по умолчанию `data/`) |
| `--extra-data <dir>` | дописать поверх: приложения-образцы для тестов (`sim/tests/fixtures`) |

Прошивка не меняется ни на байт. Симулятор подставляет только то, что на часах дают плата
и ядро Arduino:

| Часы | Симулятор |
|------|-----------|
| Плата (`Device::inst()`) | `sim_tela_device.cpp`: вывод и касания → виртуальная панель |
| `millis()` / `delay()` | виртуальные часы; `time()` тоже, старт 2026-10-30 10:09:30 UTC |
| LittleFS, залитый из `data/` | `data/` (+ `--extra-data`) в LittleFS из TelaCI при старте |
| Диск LVGL `C:` (`/littlefs`) | `sim_tela_fs.cpp`: тот же `lv_fs_stdio_init()`, но поверх LittleFS |
| Serial-консоль | ввод робота: `> app launch hello` |
| ESP, NimBLE, FreeRTOS | заглушки TelaCI (`ci/stubs`) |

Время виртуальное, поэтому скриншоты детерминированы: одинаковая прошивка даёт побайтно
одинаковые PNG.

## Робот

Сценарий — команда на строку (или через `;`), `#` — комментарий. Цель — один токен:
`@id` (элемент по id), `@id:0.9,0.5` (точка внутри), `"текст"` (видимая надпись, абзац,
клавиша, строка списка), `x,y` (пиксели).

```
> app launch hello                         # консоль прошивки — та же, что по Serial и BLE
> ui type stdin Анатолий
tap "Run"                                  # палец на панели
expect $_stdout contains "Thank you, Анатолий"
expect @dlg :hidden                        # скрыт или прокручен за край
expect @card contains "text"               # у контейнера — видимый текст внутри
shot tela_03_result
```

| Команда | Что делает |
|---------|-----------|
| `wait <ms>` | подождать (виртуальные мс) |
| `tap`, `longpress <T> [ms]`, `drag <T1> <T2> [ms]`, `press`, `move`, `release` | палец |
| `scroll @id` | прокрутить к элементу |
| `text @id <value>` | вписать текст в поле |
| `expect @id <value>`, `expect @id contains <v>` | значение виджета; числа — диапазоном `20..30` |
| `expect <@id или "текст"> :visible` / `:hidden` | виден ли на экране |
| `expect $var <value>` | переменная состояния приложения |
| `> <строка>` | строка в консоль прошивки |
| `shot <name>`, `tree <name>` | PNG экрана; JSON дерева виджетов с рамками, значениями, переполнением и id элементов |

Тап по закрытому виджету проваливается (`covered by …`) — как промахнулся бы настоящий палец.
Сценарии лежат в `sim/tests/*.sim`, приложения-образцы для них — в `sim/tests/fixtures/apps/`.

## Экраны всех приложений

```bash
python3 sim/tools/sim_screens.py --head . --base ../telaos-future --out build/screens
```

Собирает симулятор из `sim/` против обеих копий прошивки, на каждой снимает лаунчер и каждую
страницу каждого приложения (список берёт у самой прошивки — вместе с нативными и образцами),
прогоняет `sim/tests/*.sim` на `--head`, сравнивает экраны попиксельно и пишет:

| Файл | Что |
|------|-----|
| `report.md` | отчёт: что изменилось — словами и картинками, тесты робота |
| `publish/before`, `after`, `diff` | только изменившиеся экраны; на `diff` новый экран серым, изменённые пиксели — пурпурным, вокруг — жёлтая рамка |
| `status.json` | то же для машин; у изменившегося экрана — `changes`, те же слова |
| `shots-base/`, `shots-head/`, `tests/` | всё целиком: PNG и дерево виджетов (JSON) каждого экрана |

Без `--base` — просто снимки всех экранов. Только стандартная библиотека Python.

### Что изменилось — словами

Рядом с каждым снимком робот сохраняет дерево виджетов. У изменившегося экрана
`sim/tools/tree_diff.py` сравнивает деревья «до» и «после» и пишет, что заметит человек:

```
- Надпись: «The Cubic» → «Кубик»
- Появилась надпись `#hint` «Нажми кнопку»
- Кнопка «БРОСИТЬ» сдвинулась на 38 px вниз
- Кнопка «БРОСИТЬ»: ширина 336 → 384
- Блок `#lists` не помещается по высоте: +12 px
- Экран был пуст — появилось 10 элементов, в том числе «РАБОТА», «25:00», «Session 1 of 4»
```

Элементы сопоставляются по типу, id и тексту, поэтому вставленный элемент не «сдвигает»
остальные. Что едет вместе с родителем, не повторяется; соседи, сдвинутые на одно и то же,
идут одной строкой; если у элемента остались на месте начало, середина или конец, он не
сдвинулся, а изменил размер; скрытое и до и после не считается. Не больше 8 строк на экран,
остальное — числом. Если деревья совпали, а пиксели нет: «Виджеты те же — изменились только цвета, шрифты
или картинки». Одни и те же деревья всегда дают одни и те же слова. Вручную:
`python3 sim/tools/tree_diff.py before.json after.json`. Тесты:
`python3 -m unittest discover -s sim/tools -p 'test_*.py'`.

### Сколько в коде осталось C

Рефакторинг ведёт код от C на сырых указателях к типизированному C++. `sim/tools/code_meter.py`
считает в `src/` то, что типы заменяют: `strcmp` и его родню, `strstr`/`strchr`, `snprintf`,
`strcpy`/`strcat`, буферы `char x[N]`, голые `malloc`/`free`. Комментарии и строки не считаются,
шрифты (`src/font/*.c`) — тоже. В отчёте PR одна строка:

```
Сишные места в src/: 451 → 437 (−14): `strcmp` −10, `char x[N]` −4
```

Вручную: `python3 sim/tools/code_meter.py <checkout> [<база>]` — плюс самые «сишные» файлы.

## Проверка PR

`.github/workflows/pr-checks.yml`, на каждый PR:

1. **TelaCI** — `ci/build.py --mock` и `ci/test.py`, плюс тесты `sim/tools` (так же и на push
   в `main`/`future`).
2. **Simulator screens** — `sim_screens.py` против базы PR. Картинки уходят в ветку
   `sim-screens` (`pr-<номер>/<sha>/`, один коммит без истории — старые картинки не копятся),
   отчёт — одним комментарием в PR, который обновляется с каждым пушем. Закрыли PR — его
   картинки удаляются. Упал тест робота или PR не собирается — проверка красная.

PR из форков получают тот же отчёт в сводке job и в артефакте `sim-screens`, без картинок
в комментарии: у их токена нет права писать.

## Ограничения

- Сеть (BLE-мост, `fetch`) не эмулируется: такие экраны показывают «нет связи».
- Экран 480×480 (esp4848s040); другие платы — `-DTELA_SCREEN_W/H`.
- Скорость часов не эмулируется: в `--headless` всё мгновенно, в окне — в реальном времени.
- Собирается на Linux (и WSL): время подменяется ключом компоновщика GNU `--wrap=time`, у macOS
  такого нет.
