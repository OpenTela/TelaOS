# Testing principles

Кратко о том, ЧТО и КАК мы тестируем. Принцип раньше держался структурно
(тесты жили в отдельном репозитории Tela-CICD, чтобы автор тестов не подглядывал
в реализацию). Репозитории объединены (тесты теперь в `ci/`), поэтому принцип
фиксируется словами, а не границей репозитория.

## 1. Тестируем свой код = границу слоёв

Объект проверки - то, что МЫ передаём в подсистему, а не то, что подсистема из
этого вычислит. Пример: при `align="stretch"` мы проверяем, что парсер вызвал
`lv_obj_set_flex_align(..., START, ...)` и выставил детям `lv_pct(100)` по
cross-оси. Реальные посчитанные координаты виджета - зона ответственности LVGL,
не наша.

## 2. Каждый слой проверяет свой контракт и доверяет соседу

LVGL тестирует свою раскладку сам (у проекта LVGL свой CI). Мы не перепроверяем
чужую работу - это лишняя работа и выход за нашу зону. Чем точнее каждый слой
делает своё, тем крепче стык. Скорость наших тестов - следствие правильной
границы (не тащим чужой движок), а не срезанный угол.

## 3. Recording-мок - правильный инструмент, не времянка

Для проверки границы нужен мок, который ЗАПИСЫВАЕТ переданные аргументы
(`ci/stubs/lvgl_mock.h` пишет `flexCrossAlign`, `w`, `h` и т.п.). Реальные чужие
движки и reference-скриншоты не тащим: это была бы проверка чужого результата.

## 4. Тест кодирует НАМЕРЕНИЕ, а не реализацию

Иначе тест вырождается в тавтологию ("передали X -> проверили, что передали X").
Формулировка идёт от спецификации/намерения: "stretch должен растянуть по
cross-оси" -> ждём `lv_pct(100)` у детей. Это единственная защита от подгонки
теста под код; ни мок, ни реальный движок её не дают.

## 5. Дрейф API заглушек чиним точечно

Если реальный API подсистемы ушёл вперёд, а заглушка отстала (пример: msgbox в
`lvgl_mock`), это мелкая проблема совместимости - догоняем заглушку. Это не порок
подхода и не повод тащить реальный движок.

## Запуск

```
bash ci/lib/build_libs.sh            # один раз: host-сборки ckdl/lua/mbedtls
python3 ci/build.py . --mock --rebuild
python3 ci/test.py .
```

Прошивочная сборка (`pio run`) каталог `ci/` не трогает: он вне `src/`,
`include/`, `lib/`.
