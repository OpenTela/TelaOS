# CSS v0.22

CSS в TelaOS: что из CSS имеет смысл на экране часов, что уже работает и во что оно превращается
в LVGL. Браузер без JS — всё остальное должно быть: HTML (`docs/HTML_TAGS.md`) и CSS.

## Где живут стили

- `<style>` в `<app>` — для всего приложения; `<style>` на странице — для того, что после него.
- `<link rel="stylesheet" href="…">` — то же из файла: в `<app>` — для всего приложения, на странице —
  для того, что после неё. Правила считаются там, где стоит ссылка: из двух равных побеждает нижнее,
  будь то `<style>` или `<link>`, как в браузере. `href` с `/` — от корня файлов часов
  (`/system/tela.css`), без `/` — из `resources/` приложения, как `<img src>`. С `media` — только для
  экрана, которому он подходит (`media="(prefers-color-scheme: dark)"`). Пропускается, как браузер
  пропускает то, что не загрузил: другой `rel`, `rel="alternate stylesheet"`, `disabled`, адрес сети
  (`https://…`), файл, которого нет.
- `style="…"` у элемента — после всех листов, у элементов HTML и у виджетов TelaOS.
- Атрибуты TelaOS (`bgcolor=`, `color=`, `font=`…) — после CSS: виджет ставит их сам.
- Скрипт меняет класс, `id` или атрибут — CSS применяется заново (`docs/DOM.md`, «Классы и CSS»).
- Теми же селекторами скрипт находит элементы: `document:querySelectorAll(".item")`
  (`docs/DOM.md`, «Поиск по селекторам»).
- Движок: `src/ui/css_parser.cpp`. Предки элемента для селекторов — `UI::CssScope`: страница,
  `<div>`, таблицы, вкладки, `<label>` и `<button>` с HTML внутри и элементы HTML, пока строится их содержимое.

## Стиль часов

`/system/tela.css` — вид TelaOS для обычного HTML, без классов (`docs/ROADMAP.md`, этап 7,
решения 22 и 23). Вид браузера по умолчанию остаётся; стиль — слой CSS поверх него, его подключают:

```html
<app>
  <link rel="stylesheet" href="/system/tela.css">
  <style>/* своё — после него: из двух равных правил побеждает нижнее */</style>
  ...
</app>
```

В нём (0.2):
- тёмный экран и светлый текст, как у приложений TelaOS без HTML: фон и цвет `html`, `body`;
  заголовки — цветом текста, как в браузере (без стиля часы рисуют `h2`–`h6` чуть тусклее);
- ссылки — цветом акцента;
- кнопки — `<button>`, `<input type="button">`, `submit`, `reset` — как у TelaOS: синие, скруглённые,
  не ниже 44 px, текст 16 px, поля 10 px 16 px. Под пальцем (`:active`) — темнее, выключенные — бледнее;
- поля (`text`, `password`, `email`, `search`, `tel`, `url`, `number`), `textarea` и `select` — через
  весь экран, не ниже 44 px, текст 16 px на карточке экрана, рамка 1 px, скругление как у кнопок;
  `textarea` — высотой в свои строки (`rows`);
- флажки и радио — 22 px; вокруг них ещё 15 px зоны нажатия;
- `color-scheme: dark` и `accent-color`: то, что браузер рисует сам (флажок, ползунок, стрелку
  `select`), — тёмным и цветом акцента, как на часах.

Тема — те же переменные после файла:

```html
<link rel="stylesheet" href="/system/tela.css">
<style> :root { --tela-accent: #4caf50; --tela-pressed: #388e3c; } </style>
```

| Переменная | Что | Значение |
|---|---|---|
| `--tela-bg` | фон экрана | `#0a0a12` |
| `--tela-text` | текст | `#fafafa` |
| `--tela-accent` | кнопки и ссылки | `#2196f3` |
| `--tela-on-accent` | текст на кнопке | `#ffffff` |
| `--tela-pressed` | кнопка под пальцем | `#1976d2` |
| `--tela-radius` | скругление | `10px` |
| `--tela-tap` | наименьшая высота того, что нажимают | `44px` |
| `--tela-surface` | поле и список на экране | `#1e1e2a` |
| `--tela-line` | их рамка | `#3a3a4c` |

Chromium с тем же файлом показывает страницу так же, и светлую тему тоже. Судья проверяет это в
каждом PR: `html_tags` со стилем — строка «Со стилем часов» в отчёте и экраны `html_tags_tela`
(`docs/SIMULATOR.md`); он сверяет рамки, цвета — снимки экранов.

## Значения

- Значение, которое не читается, выбрасывает своё объявление — как в браузере. Свойство тогда
  наследуется или остаётся как было: `color: rgb(1, 2)` не красит в чёрный, `font-size: inherit` не
  сбрасывает шрифт на 16px.
- Длины: число без единиц или `px`, `em`, `rem`, `vw`, `vh`. Шрифт берётся ближайший сверху из
  шрифтов прошивки (16, 32, 48, 72), и `em` — это он.
- Прозрачность цвета — `text_opa` для `color` и `bg_opa` для фона. `transparent` и
  `background: none` убирают фон.
- `--x: …` — переменная: её видят элемент и всё внутри него, `:root { --x: … }` — все.
  `var(--x, запасное)` берёт ближайшую; если её нет и запасного нет, объявление выбрасывается.
  Переменные, которые ссылаются друг на друга по кругу, недействительны.

## Строчные элементы

У слов внутри абзаца (`<a>`, `<span>`, `<b>`) нет своих объектов LVGL: это куски одной надписи или
группы спанов. Правила для них (`nav a`, `.menu a`, `a.btn`) дают то, что умеет кусок текста:
`color`, `font-size`, `font-weight`, `font-style`, `text-decoration`.

## Ограничения

- Правило с потомком действует на элементы, которые строятся после `<style>`, как и любое правило
  на странице.
- Когда `class="{var}"` меняется, перечитываются только правила из одних классов — как и раньше;
  `var()` в них видит только свои переменные и `:root`.
- `:root` — для переменных, `:root .x` не срабатывает. Из `html` и `body` страница берёт `background`
  и `color`, как браузер — холст: фон — `html`, а если у него нет — `body`; цвет текста — `body`, а
  если у него нет — `html`. `bgcolor=""` страницы остаётся её. Остальные свойства `:root`, `html`,
  `body` ни на что не действуют: страница — не элемент со стилем.
- `rem` — всегда 16px: `html { font-size }` его не меняет.
- `em` и `%` в `font-size` строчного элемента — от шрифта строчного элемента вокруг или блока по
  умолчанию (`h1` — 48px); `font-size` самого блока из CSS тут не учитывается.
- `border-radius` в процентах — только круг (50% и больше): размер элемента в это время ещё не известен.
- `<th>` строится как `<td>`: правила `th` к нему не применяются.
- `margin` действует там, где раскладывает LVGL: в потоке HTML и во flex. У TelaOS-виджета
  с `x`/`y` его нет. `margin: 0 auto` не центрирует.
- У рамки одна толщина и один цвет: если стороны заданы разными, берутся у стороны, заданной
  последней. `dashed`, `dotted`, `double` и другие стили рисуются сплошной линией.
- `box-shadow: inset` не рисуется: LVGL рисует тень только снаружи.
- `position: absolute` считается от родителя, а не от ближайшего предка с `position`;
  `fixed` — тоже от родителя, но не прокручивается вместе с ним.
- Элементы flex-контейнера — его блоки и виджеты. Строчный текст внутри (`<nav><a>…</a> <a>…</a></nav>`)
  остаётся одной строкой, а не отдельными элементами.
- `align-items: stretch` — по умолчанию в CSS — в LVGL нет: элементы остаются своего размера.
- `line-height`, `letter-spacing` и `text-decoration` LVGL передаёт детям готовым числом: `line-height: 1.5`
  у блока даёт детям с другим шрифтом тот же отступ между строками в пикселях.
- `white-space: nowrap` и `text-overflow` действуют на одну надпись: у абзаца со ссылками или
  `sup`/`sub` (он строится по словам) их нет.
- `text-transform` нет: значение `{var}` меняется после построения, и преобразованный текст его бы терял.
- В состоянии (`:active` и другие) меняется вид: цвет, фон, прозрачность, радиус, рамка, обводка, тень,
  `transform`, оформление текста. Размеры, отступы и раскладка остаются у элемента без состояния.
- Состояние предка или соседа (`.menu:active a`, `input:checked + label`) — нет: в LVGL стиль
  состояния есть только у самого виджета.
- Когда состояний несколько сразу (флажок отмечен и нажат), LVGL берёт стиль старшего:
  `:disabled`, затем `:active`, `:focus`, `:checked` — а не правило, что ниже в листе.
  `.x:checked:active` задаёт вид для обоих сразу.
- Что выступает за блок, строку или элемент списка HTML (обводка, тень, `transform`), видно
  на 24px, дальше обрезается. `<div>` TelaOS обрезает по своему краю, пока ему не сказать
  `overflow: visible`.
- `transition` берётся у элемента без состояния: `transition` внутри `:active { }` не действует.
- Состояние внутри `:not()` и `:is()` (`:not(:checked)`, `:is(:hover, :focus)`) — нет: в LVGL нет
  стиля «не нажат». `:not()` с таким селектором выпадает целиком, а `:is()` и `:where()` теряют
  только его — как браузер с тем, что не понимает.
- `::placeholder` — без состояния (`input:focus::placeholder` не читается) и без `font-size`.
- `@media` читается один раз, когда читается лист: экран часов не меняется. Признак, которого
  движок не знает, не выполняется, и `not` перед ним тоже — как в браузере.
- Место среди соседей и сами соседи читаются из текста страницы: класс соседа — каким он написан
  (`class="{var}"` не подставляется). Поля HTML (`<input type="text">`, `"range"`, `"submit"`,
  `<textarea>`) строятся виджетами TelaOS из своего текста: своего места среди соседей у них нет.
- `transform` в LVGL — всегда сдвиг, масштаб, поворот, в каком бы порядке ни шли функции.
  `transform` без `translate()` сохраняет сдвиг от `position: relative`, с ним — заменяет.
