# Как вносить изменения v0.4

Правила TelaOS для всех, кто меняет код, — людей и моделей. Ничего здесь не требует конкретной
модели, сервиса или редактора. План, решения и то, что ждёт проверки на часах, — в
[`docs/ROADMAP.md`](docs/ROADMAP.md).

## Changelog

- **v0.4**: Правила — в репозитории (до этого `PROJECT_RULES` v0.3 лежал вне его). Новое: главное
  правило — проверка без автора; ветки и PR, стопки PR; железо; `if` и условия; память `M::` и `P::`;
  `lib/lvgl`. Структура `src/` списком убрана: она устарела, смотреть по коду.
- **v0.3**: Логирование (`Log::`).
- **v0.2**: Структура `src/` с `core/`.
- **v0.1**: Уникальные имена файлов, версии документов.

## Главное

Изменение принимается, когда его может проверить кто угодно — без автора и без его рассказа:
- **есть объективный судья:** тест, пиксели симулятора, рамки и кадры против Chromium, число в
  отчёте PR. «Выглядит правильно» — не проверка;
- **нет судьи — сначала судья.** Так появились судья раскладки (#62), судья анимаций (#88) и
  перерисовка в покое (#82): сначала число, потом правки, которые его двигают;
- **то, что зависит от часов**, сливается только после проверки на часах (раздел «Железо»).

## Ветки и PR

- Работа идёт в `future`. Каждое изменение — PR в `future`; прямо в `future` и `main` не пушат.
- Один PR — одно изменение. Ошибка, найденная по дороге, — отдельный PR со своим тестом.
- Рефакторинг не меняет поведения: в отчёте PR «изменилось: 0» на всех экранах и случайных
  страницах, а сишных мест меньше.
- **Стопка PR.** PR, который стоит на другом, смотрит в его ветку; порядок — в первой строке
  описания. Когда нижний слит, следующий переводят на `future` и только потом сливают: сам GitHub
  его не переведёт, автоудаление веток в репозитории выключено. Иначе он сольётся в ветку под ним, а
  не в `future` — так было с #41–#43 (их перенёс #44) и с #83–#84.
- **Описание PR:** что и зачем; что покажет отчёт CI; тесты с числами; если изменение зависит от
  часов — «Проверить на часах» по шагам.
- Пустых коммитов и закрытия-открытия PR ради перезапуска CI нет: зелёный CI значит, что этот код
  прошёл тесты.
- Сливает владелец проекта.

## Проверка

CI (`.github/workflows/pr-checks.yml`) на каждый PR делает то же, что можно сделать у себя на
Ubuntu 24.04:

```bash
# TelaCI: весь src/ на заглушках и его тесты; тесты инструментов симулятора
sudo apt install libmbedtls-dev
bash ci/lib/build_libs.sh
python3 ci/build.py . --mock && python3 ci/test.py .
python3 -m unittest discover -s sim/tools -p 'test_*.py'

# Симулятор: роботы, экраны против базы, судьи (Chromium), случайные страницы
sudo apt install cmake ninja-build libsdl2-dev libpng-dev libmbedtls-dev
pip install playwright==1.63.0 && python3 -m playwright install --with-deps chromium
python3 sim/tools/sim_screens.py --head . --base <папка с базой PR> --out build/screens --pages 300

# То же под ASan и UBSan
python3 sim/tools/sim_asan.py --head . --out build/asan --pages 300

# Прошивка
pio run -e esp4848s040 && pio run -e twatch2020
```

Отчёт — `build/screens/report.md`: экраны картинками и словами, тесты робота, сишные места,
совместимость с Chromium, анимации, перерисовка в покое, память. Подробно — `docs/SIMULATOR.md`,
тесты — `docs/TESTING.md`.

## Железо

- **Только после часов.** То, что зависит от часов (дисплей, сон, PMU, BLE, OTA, разделы флеша),
  сливается после проверки на часах по шагам из описания PR. Пока проверки не было, шаги лежат и в
  `docs/ROADMAP.md`, раздел «Ждёт часов».
- **Необратимого не делаем** без решения владельца: eFuse, Secure Boot, шифрование флеша.
- **Платформа без часов не меняется** (решение 12 в `docs/ROADMAP.md`): Arduino-ESP32 2.0.17,
  ESP-IDF 4.4.7, GCC 8.4. Платы в работе — esp4848s040 и twatch2020.
- **Связь с часами:** USB-консоль и BLE, протокол — `docs/CONSOLE_PROTOCOL_SPEC.md`. По BLE —
  `tools/ble_assistant.py` (`--scan`, `--addr`, `--daemon`; зависимости — `tools/requirements.txt`).

## Код

- **C++17:** прошивку собирает GCC 8.4.
- **Типы, а не Си:** `std::string_view` вместо `strcmp`, контейнеры вместо `char x[N]` и `malloc`.
  Отчёт PR считает сишные места в `src/` (`sim/tools/code_meter.py`); их число не растёт.
- **Память:** `M::` — DRAM, для статики до `psramInit()`; `P::` — PSRAM, для данных во время работы
  (`src/utils/psram_alloc.h`: `String`, `Array`, `Map`, `Ptr`).
- **`lib/lvgl` не правим:** ошибку LVGL обходим из кода TelaOS (#72 вместо #61). В `future` уже
  есть одна правка — `lv_span.c` (#64, с пометкой `TelaOS:`); оставить ли её — открытый вопрос в
  `docs/ROADMAP.md`.
- **`if`:** тело — всегда на своей строке, без исключений. Фигурные скобки для одной команды не
  обязательны. Простое условие пишется прямо в `if`. Длинное выносится в переменную с именем,
  которое говорит, что оно значит («Extract Variable» у Фаулера, раньше «Introduce Explaining
  Variable»):

  ```cpp
  const bool noRoom = lv_obj_get_content_width(cont) <= 0 || lv_obj_get_content_height(cont) <= 0;
  if (noRoom)
      lv_event_stop_processing(e);
  ```

  Это для нового и изменённого кода; старый правится, когда его трогают.
- **Имена файлов уникальны во всём проекте:** `lua_engine.cpp` и `ui_engine.cpp`, а не два
  `engine.cpp`. Так файл находится по имени, скрипты не путаются, история git и вкладки редактора
  однозначны. C/C++ — `prefix_name.cpp/h`, Python — `snake_case`. Переносишь файл — имя не меняешь,
  обновляешь все `#include` и проверяешь сборку.
- **Логи:** `LOG_E`, `LOG_W`, `LOG_I`, `LOG_D`, `LOG_V` из `utils/log_config.h` с категорией
  (`Log::UI`, `LUA`, `STATE`, `APP`, `BLE`, `CRYPTO`, `SD`); в файле нужен
  `static const char* TAG`. Уровень по умолчанию — `Info`. Консоль: `log`, `log info`,
  `log ui verbose`.

## Документы

- **Версия и Changelog** в каждом документе: версия — в заголовке, под ним `## Changelog` с
  последним изменением сверху. Изменил содержание — поднял версию. Если два PR поднимают версию
  одного документа, тот, что сливается позже, перенумеровывается.
- **Что работает и чего нет** — `docs/HTML_TAGS.md`, `docs/CSS.md`, `docs/DOM.md`. Ограничение
  допустимо, если оно записано там.
- **Решения — в `docs/ROADMAP.md`.** Решение, принятое в разговоре, записывается туда; не записано —
  для проекта его нет.
